# 调研与决策：助手形态产品底座选型

> 2026-11-07。候选：OpenMausBot、CopilotKit/openbot、TencentCloud/Octop。
> 源码副本：`research/`（只读参考）。

## 结论

**以 Octop 为产品底座做白标改造 + 后端打通；OpenMausBot 与 openbot 仅作设计参考。**

## 需求基准

政企（政府/企业）客户场景：终端用户不管理「项目/工作区」，而是使用「助手/智能体」。
需要：助手管理、知识库、企业身份接入、私有化部署、统一后端管理（资产/模型/审计下发）。

## 三候选对比

| | OpenMausBot | openbot (CopilotKit) | Octop (腾讯) |
|---|---|---|---|
| 形态 | 本地优先 Electron 聊天应用，侧栏 bot=真实 CLI agent | 自托管 AI 同事平台：Bot 走 AG-UI | 单进程多用户助手平台：专家+全渠道 |
| 栈 | Electron+React19+TS | React+Hono/Bun+Postgres+Tauri | Python3.12 FastAPI+React18/AntD |
| 治理 | 无管理面 | CEL 策略网关+全量审计+容器隔离 | JWT 多用户+管理员+审批+PII 脱敏+审计 |
| 部署 | 单机桌面 | Compose/K8s 多服务 | 单进程，SQLite/PG，离线可用 |
| 许可证 | Apache-2.0+NOTICE+CLA | MIT | MIT |

### 落选原因

- **openbot**：能力最贴治理面，但基础设施假设（Postgres 必备、supervisor 持
  Docker socket 开 per-bot 容器、外部 CopilotKit Intelligence、AG-UI 协议）
  与本项目「单进程、私有化、少外部依赖」冲突。吸收项：工具网关模型
  （resolve→CEL policy→audit→execute）与 `initiator_kind` 审计分类
  （person/routine/handoff/memory/deployment）——作为 spec 参考。
- **OpenMausBot**：同栈但无控制面，所有管理面都要自建。吸收项：`customAcp`
  引擎驱动抽象（任意 ACP CLI 当 bot 引擎，含模型目录探测与 ACP 权限桥）、
  Bot API、routines、approval 分级——作为 spec 参考。

### Octop 命中点（实测验证，非 README）

- 专家（=助手）一等公民：人设 + 独立工作区 + provider + 通道 + cron + 知识绑定；
  专家市场/内网市场/AgentTeams 主持调度。
- 知识库 RAG 内置，可部署内共享。
- 身份：OIDC + LDAP + 飞书/企微/钉钉 SSO adapter 全内置；LDAP 自动建号+组映射；
  MFA/WebAuthn。
- 市场：`OCTOP_PORTAL_ORIGIN` 指内网目录（两个 JSON + zip 下载），可挂到
  hxai-admin 输出。
- 审计表 + `/admin/audit-log`；约 50 个权限键；70+ API 路由（用户/角色/用户组/
  邀请/可观测/TLS/备份/安全/用量/存储后端/桥接/MCP）。
- 多渠道统一入口（Web/IM/cron/API/ACP→同一 HarnessProcessor）。

## 差距与补齐（详见《改造方案》）

1. 无 MySQL → 接受 PostgreSQL。
2. HX SSO → hxai-admin 补 OIDC IdP 端点（id_token 须 RS256/ES256）。
3. 模型统一下发 → 经 Octop REST API provisioning。
4. 资产市场 → hxai-admin 输出 Octop 市场协议 + 专家包转换器。
5. 白标 → 只改可见层（文案 zh/en、logo/mascot/图标、标题、Wails 壳名）。
